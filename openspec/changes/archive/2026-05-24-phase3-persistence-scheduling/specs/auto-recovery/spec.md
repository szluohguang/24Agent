## 新增需求

### 需求：SSE 流自动重连（指数退避）
当全局 SSE 流断开或标记为陈旧时，系统必须自动重连，采用指数退避策略。
退避计划：1 秒 → 2 秒 → 4 秒 → 8 秒 → 16 秒 → 32 秒 → 60 秒（上限）。
重连成功后，退避重置为 1 秒。
最大重连尝试次数必须可配置（默认：无限制）。

#### 场景：断开后 SSE 重连
- **WHEN** SSE 流断开
- **THEN** 系统等待 1 秒后尝试重连
- **THEN** 成功后，恢复所有活跃会话的事件订阅
- **THEN** 创建时间线条目："SSE 在 <时长> 后重新连接"

#### 场景：重复失败后退避增加
- **WHEN** 重连连续失败 5 次
- **THEN** 尝试之间的等待时间达到 32 秒

### 需求：挂起会话恢复
当检测到会话挂起时（通过看门狗或失败的心跳），系统必须：
1. 通过 `abortSession()` 中止挂起的会话
2. 增加 `retryCount`
3. 如果 `retryCount < maxRetries`，创建新会话并重新分发
4. 如果 `retryCount >= maxRetries`，将任务标记为失败

#### 场景：挂起会话被恢复
- **WHEN** 会话被标记为挂起
- **THEN** 会话被中止
- **THEN** 任务使用新会话重新分发
- **THEN** 创建时间线条目："会话挂起，重试 #<次数>"

#### 场景：挂起会话超出最大重试次数
- **WHEN** 会话挂起且 retryCount >= maxRetries
- **THEN** 任务标记为失败
- **THEN** 创建时间线条目："会话挂起，超出最大重试次数"

### 需求：启动时任务恢复
在应用程序启动时，系统必须检查所有持久化任务并执行恢复操作：
- `pending` 任务（依赖已满足）：自动分发
- `running` 任务：中止旧会话，重新分发
- `failed` 任务：如果 retryCount < maxRetries 则重试
- `completed` 任务：保持原样

#### 场景：重启时恢复运行中任务
- **WHEN** 应用程序启动并在数据库中发现运行中任务
- **THEN** 每个运行中任务被中止（清理旧会话）
- **THEN** 每个任务以递增的 retryCount 重新分发

### 需求：优雅关闭时保存状态
在 SIGINT/SIGTERM 时，系统必须在退出前将所有内存状态刷新到 SQLite。
关闭超时必须可配置（默认：5 秒）。

#### 场景：优雅关闭时保存状态
- **WHEN** 进程收到 SIGINT
- **THEN** 所有待处理的状态变更刷新到 SQLite
- **THEN** 进程正常退出
