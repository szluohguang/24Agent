# persistence-recovery — 持久化与恢复黑盒测试

## 概述

系统的任务、配置、定时任务等信息通过 SQLite 持久化存储。页面刷新或系统重启后数据不丢失。

## 测试用例

### 操作 1: 页面刷新后数据保持

- **页面状态**: 任务树中有多个任务（包含 pending / running / completed 等状态），权限级别为 strict，预算限额已修改
- **用户操作**: 按 F5 刷新页面
- **预期结果**:
  - 页面重新加载后，所有任务仍然在任务树中
  - 各任务的状态与刷新前一致
  - 控制栏的权限级别显示为 strict（与刷新前一致）
  - 系统概览中的预算限额、花费等数据正确

### 操作 2: 系统重启后任务恢复

- **页面状态**: 任务树中有任务处于 pending 状态，有任务处于 running 状态
- **用户操作**: 停止后端服务器（Ctrl+C），重新启动（npm run dev）
- **预期结果**:
  - 页面刷新（或自动重连）后：
  - pending 状态的任务保持 pending
  - running 状态的任务已被恢复机制处理（中止旧 session，重新分发或标记为 pending）
  - 已完成任务的状态保持 completed

### 操作 3: 系统重启后配置保持

- **页面状态**: 权限级别改为 strict，预算限额改为 100，并行度改为 5，添加了一条定时任务
- **用户操作**: 完全重启后端（停止 → 启动）
- **预期结果**:
  - 页面刷新后权限级别仍为 strict
  - 预算限额仍为 100
  - 并行度仍为 5
  - 定时任务列表仍然存在，cron 定时器恢复

### 操作 4: 系统崩溃恢复

- **页面状态**: 有多个任务处于不同状态
- **用户操作**: 模拟进程崩溃（强制终止），然后重新启动系统
- **预期结果**:
  - 系统启动后自动加载持久化数据
  - pending 状态的任务被重新分发
  - running 状态的任务 session 被清理，任务被重试
  - 已完成的任务不受影响
