# connection-management — 连接管理黑盒测试

## 概述

WebUI 通过 WebSocket 与后端保持长连接。用户在控制栏可以看到连接状态指示，连接断开后自动重连。

## 测试用例

### 操作 1: 正常连接

- **页面状态**: 打开浏览器访问 http://localhost:3000
- **用户操作**: 等待页面加载完成（无需操作）
- **预期结果**:
  - 底部控制栏显示 "Connected" 状态文字
  - 状态指示灯为绿色
  - 任务树、时间线等面板正常显示（或显示空状态）
  - 控制栏的操作按钮处于可用状态

### 操作 2: 连接断开

- **页面状态**: 页面已加载且显示 "Connected"
- **用户操作**: 停止后端服务器（按 Ctrl+C 停止 orchestrator）
- **预期结果**:
  - 控制栏状态由 "Connected" 变为 "Disconnected"
  - 状态指示灯变为红色
  - 控制栏的操作按钮（创建/分发等）变为禁用或灰色
  - 页面可能显示断连提示条

### 操作 3: 自动重连

- **页面状态**: 页面显示 "Disconnected"，操作按钮禁用
- **用户操作**: 重新启动后端服务器（npm run dev）
- **预期结果**:
  - 控制栏显示 "Reconnecting..." 状态
  - 短暂等待后状态恢复为 "Connected"
  - 指示灯变回绿色
  - 操作按钮恢复可用
  - 页面状态自动同步（任务树、时间线刷新）

### 操作 4: 断连期间尝试操作

- **页面状态**: WebSocket 连接断开，操作按钮禁用
- **用户操作**: 尝试点击 Disabled 状态的"创建"或"Dispatch"按钮
- **预期结果**:
  - 按钮无响应（已禁用）
  - 或弹出提示"连接已断开，请等待重连"
  - 没有错误发生

### 操作 5: 重连后状态同步

- **页面状态**: 后端运行时创建了若干任务，然后断开又重连
- **用户操作**: 后端先停止再启动，等待页面自动重连
- **预期结果**:
  - 重连成功后，页面状态与后端同步
  - 之前创建的任务在任务树中正确显示
  - 运行中的任务状态正确展示
