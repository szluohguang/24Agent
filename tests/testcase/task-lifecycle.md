# task-lifecycle — 任务生命周期黑盒测试

## 概述

用户通过 WebUI 控制栏创建任务，在任务树中查看和管理，经过分发→运行→完成/失败的全生命周期。测试覆盖所有用户可执行的任务操作。

## 测试用例

### 操作 1: 创建任务

- **页面状态**: 左侧任务树为空，底部控制栏显示输入框和"创建"按钮
- **用户操作**: 在输入框中输入"优化用户登录模块的性能"，点击"创建"按钮
- **预期结果**:
  - 任务树中出现一个新的任务节点
  - 节点显示任务的描述文字"优化用户登录模块的性能"
  - 节点旁显示状态标签 `pending`（灰色或默认颜色）
  - 控制栏输入框自动清空
  - 时间线面板出现一条 "Task added: 优化用户登录模块的性能" 的事件

### 操作 2: 连续创建多个任务

- **页面状态**: 任务树上已有 1 个任务
- **用户操作**: 连续创建 3 个任务，分别输入不同描述
- **预期结果**:
  - 任务树中出现 4 个任务节点
  - 每个节点的描述文字正确
  - 每个节点都有唯一的 ID（可在 UI 上识别）
  - 任务按创建时间排序（最新的在顶部或底部）

### 操作 3: 创建带依赖的任务

- **页面状态**: 任务树中已有任务 A（pending）
- **用户操作**: 创建任务 B，在依赖选项中选中任务 A
- **预期结果**:
  - 任务树中任务 B 节点显示依赖标记（如箭头或缩进）
  - 任务 B 的状态为 `pending`
  - 任务 B 的详细信息中显示依赖关系

### 操作 4: 分发任务

- **页面状态**: 任务树中有一个 `pending` 状态的任务节点，旁边有"Dispatch"按钮
- **用户操作**: 点击该任务节点的"Dispatch"按钮
- **预期结果**:
  - 任务节点的状态标签由 `pending` 变为 `running`（蓝色）
  - 中间面板（StreamConsole）开始显示流式文本输出
  - 控制栏显示当前有任务正在运行
  - "Dispatch"按钮变为禁用状态或消失
  - 时间线记录 "Task dispatched" 事件

### 操作 5: 查看任务流式输出

- **页面状态**: 任务正在运行，中间面板为 StreamConsole
- **用户操作**: 观察中间面板的内容变化
- **预期结果**:
  - 面板实时追加文本内容（逐 token 更新）
  - Shell 命令输出、工具调用、文本回复用不同颜色区分
  - 面板自动滚动到底部保持最新内容可见
  - 面板顶部显示当前 sessionId

### 操作 6: 任务自动完成

- **页面状态**: 任务正在运行，StreamConsole 持续输出
- **用户操作**: 等待任务执行完毕（无需操作）
- **预期结果**:
  - StreamConsole 输出终止
  - 任务节点状态由 `running` 变为 `completed`（绿色）
  - 时间线记录 "Task completed" 事件，包含 cost 和文件变更摘要
  - 系统概览中完成任务数 +1

### 操作 7: 任务失败（重试用尽）

- **页面状态**: 任务正在运行，StreamConsole 输出错误信息
- **用户操作**: 等待自动重试（无需操作）
- **预期结果**:
  - 任务自动重试，状态短暂变为 `retrying`（若有此状态）
  - 重试后再次失败
  - 达到最大重试次数后，状态变为 `failed`（红色）
  - 节点显示错误摘要信息
  - 时间线记录 "Task failed" 事件

### 操作 8: 中止运行中的任务

- **页面状态**: 任务正在运行（`running`），节点旁有"Abort"按钮
- **用户操作**: 点击"Abort"按钮
- **预期结果**:
  - 任务状态立即变为 `failed`
  - StreamConsole 输出停止
  - 时间线记录 "Task aborted" 事件
  - 系统概览中运行任务数 -1

### 操作 9: 删除已完成任务

- **页面状态**: 任务状态为 `completed`，节点旁有"Delete"按钮
- **用户操作**: 点击"Delete"按钮
- **预期结果**:
  - 该任务节点从任务树中移除
  - 时间线记录 "Task deleted" 事件
  - 系统概览中总任务数 -1

### 操作 10: 删除运行中的任务（应被阻止）

- **页面状态**: 任务正在运行（`running`），节点旁有"Delete"按钮
- **用户操作**: 点击"Delete"按钮
- **预期结果**:
  - 页面弹出错误提示"无法删除正在运行的任务"
  - 任务保留在任务树中，状态不变
  - 任务树未发生任何变化

### 操作 11: 依赖任务自动分发

- **页面状态**: 任务 A（pending）和任务 B（pending，依赖 A），均未分发
- **用户操作**: 点击任务 A 的"Dispatch"按钮，等待 A 完成
- **预期结果**:
  - A 完成后状态变为 `completed`
  - B 自动从 `pending` 变为 `running`（无需用户手动分发）
  - StreamConsole 自动切换到 B 的输出
  - 时间线记录 "Task B dispatched (dependencies met)" 事件

### 操作 12: 预算超限阻止分发

- **页面状态**: 系统概览显示已花费预算 >= 预算上限
- **用户操作**: 尝试分发一个 `pending` 任务，或创建一个新任务
- **预期结果**:
  - 页面弹出提示"预算已超限，无法分发新任务"
  - 任务保持 `pending` 状态
  - 分发操作被阻止

### 操作 13: 并行度满时排队

- **页面状态**: 已有 3 个任务正在运行（maxParallel=3）
- **用户操作**: 创建并分发第 4 个任务
- **预期结果**:
  - 第 4 个任务状态保持 `pending`（或显示 `queued`）
  - 有排队提示信息
  - 当某个运行中任务完成后，第 4 个任务自动变为 `running`

### 操作 14: 继续会话（continuePrompt）

- **页面状态**: 任务处于 `running` 状态，StreamConsole 有之前的输出
- **用户操作**: 在控制栏的输入框中输入"继续修改"，点击"发送"按钮
- **预期结果**:
  - Agent 收到新的 prompt 指令
  - StreamConsole 继续输出新的内容
  - 时间线记录 follow-up prompt 事件
