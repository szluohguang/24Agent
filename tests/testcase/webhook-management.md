# webhook-management — Webhook 配置黑盒测试

## 概述

用户在设置弹窗的 Webhook 标签页中管理外部回调通知的配置：添加 URL、选择监听事件类型、启用/禁用、编辑、删除。

## 测试用例

### 操作 1: 添加 Webhook

- **页面状态**: 打开设置弹窗，切换到 Webhook 标签页，显示添加表单和空列表
- **用户操作**: 在 URL 输入框中填写 "https://example.com/callback"，勾选事件"task.completed"和"task.failed"，点击"添加"按钮
- **预期结果**:
  - Webhook 列表中出现新条目
  - 条目显示 URL 地址
  - 条目显示监听的事件列表
  - 条目状态为"已启用"（绿色标签或开关打开）
  - 添加表单清空
  - 上方出现"Webhook 已添加"提示

### 操作 2: Webhook 触发通知

- **页面状态**: 存在一个监听 task.completed 事件的 Webhook
- **用户操作**: 创建并完成一个任务（或等待现有任务完成）
- **预期结果**:
  - 任务完成时，配置的 URL 收到 HTTP POST 请求
  - 请求体包含事件类型、时间戳、任务 ID、描述、状态、结果摘要等信息
  - 请求头 Content-Type 为 application/json

### 操作 3: 启用/禁用 Webhook

- **页面状态**: Webhook 列表中有一个已启用的条目，旁边有开关
- **用户操作**: 点击开关切换到禁用状态
- **预期结果**:
  - 该 Webhook 状态变为"已禁用"
  - 后续发生匹配事件时不会向该 URL 发送请求
  - 重新打开页面，禁用状态保持

### 操作 4: 删除 Webhook

- **页面状态**: Webhook 列表中有一个条目，旁边有"删除"按钮
- **用户操作**: 点击"删除"按钮，在确认框中点击"确认"
- **预期结果**:
  - 该条目从列表中移除
  - 后续发生任何事件都不会向该 URL 发送请求
  - 上方出现"Webhook 已删除"提示

### 操作 5: 编辑 Webhook

- **页面状态**: Webhook 列表中有一个条目，旁边有"编辑"按钮
- **用户操作**: 点击"编辑"按钮，修改 URL 或勾选/取消事件，点击"保存"
- **预期结果**:
  - 列表中该条目的 URL 或事件列表更新
  - 后续按新配置发送通知
  - 上方出现"Webhook 已更新"提示
